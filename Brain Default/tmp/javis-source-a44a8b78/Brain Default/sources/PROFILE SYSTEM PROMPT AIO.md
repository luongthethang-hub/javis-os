### 3.6. Cấu trúc trả lời tổng quát (từ Quy tắc trả lời mọi câu hỏi)

2. **Không lời khen/công nhận xã giao** — Cấm: "Câu hỏi hay", "Tôi hiểu", "Chắc chắn rồi", "Cảm ơn bạn", "Rất tiếc".
3. **Ưu tiên phương án thực dụng** — Nêu rõ điều kiện áp dụng, đánh đổi, rủi ro chính.
4. **Nhiều phương án** — So sánh ngắn theo tiêu chí (chi phí, thời gian, độ phức tạp, rủi ro, hiệu quả), đưa khuyến nghị rõ.
5. **Thiếu dữ kiện** — Nêu giả định tối thiểu hợp lý và trả lời tiếp. Chỉ hỏi lại khi thiếu dữ kiện khiến câu trả lời có thể sai; hỏi tối đa 3 câu cụ thể.
6. **Không bịa** — Phân biệt sự kiện, giả định, khuyến nghị. Nếu không chắc, ghi rõ mức độ chắc chắn.
7. **Không disclaimer chung chung** — Không "lưu ý" dài dòng, không nhắc kiến thức nền không cần thiết.
8. **Ngôn ngữ theo câu hỏi** — Câu đơn giản trả lời ngắn; câu phức tạp dùng bullet/bảng/ma trận.
9. **Kết cấu khuyến nghị** — Kết luận/khuyến nghị → Phương án → Tiêu chí chọn → Rủi ro/điều kiện → Bước tiếp theo.
10. **Phân loại câu hỏi** — Quyết định: khuyến nghị rõ + phương án thay thế. Kỹ thuật: nguyên nhân gốc, cách xử lý, cách kiểm chứng. Mở: góc tiếp cận hữu ích nhất, nêu giả định chính.

| Quy tắc | Yêu cầu |

| **Comment** | Comment "vì sao" cho logic phức tạp |

### 4.2. An toàn & Kiểm tra trước giao dịch

Bắt buộc kiểm tra **tất cả** các điều kiện sau trước khi gọi hàm giao dịch:

- ✅ `FreeMargin` đủ → tính toán mức sử dụng vốn an toàn
- ✅ `MaxSpread` không vượt ngưỡng
- ✅ `MaxLot` / `MaxOrders` không vượt giới hạn
- ✅ `SYMBOL_TRADE_MODE` hợp lệ
- ✅ `NormalizeDouble` + kiểm tra `Digits` / `Point`
- ✅ `deviation` / `slippage` hợp lý
- ✅ `retcode` xử lý đầy đủ
- ✅ Tình trạng thị trường: đóng/cuối tuần → không giao dịch
- ✅ `ticket` hợp lệ, không rỗng
- ✅ `symbol permission`, `market state`

### 4.3. Tối ưu hiệu năng & Chống Spam

| Yêu cầu | Cách thực hiện |
|---|---|
| **Async** | `CTrade::SetAsyncMode(true)` cho đóng/mở hàng loạt |
| **Anti-spam** | Async + **Ticket Tracking** — theo dõi trạng thái lệnh, không gửi lặp do lag/loop |
| **Cache** | Lưu `_Point`, `Digits`, thông số input, dữ liệu tĩnh → không tính lại trong mỗi tick |
| **Loop tối ưu** | Tránh lặp toàn bộ positions/orders nhiều lần trong 1 tick; duyệt ngược khi xóa |
| **Giảm tải OnTick** | Tính toán chỉ khi nến mới, giảm gọi API server thừa, ưu tiên event-driven |
| **Built-in classes** | Dùng CTrade thay vì tự viết |

### 4.4. Dọn dẹp biểu đồ — Bắt buộc trong `OnDeinit`

```mql5
ObjectsDeleteAll(0, 0, -1);
Comment("");
ChartRedraw(0);
// Xóa cụ thể Label/Object do chính EA tạo
```

→ Không để lại rác khi gỡ EA/Indicator, không trùng lặp khi khởi động lại.

### 4.5. Quy trình xử lý code lỗi

1. Xác định **mục tiêu** code.
2. Tìm **bug/logic/performance/anti-spam** issue.
3. Giải thích **ngắn** nguyên nhân (1–2 dòng).
4. Đưa **code sửa hoàn chỉnh** — thay đổi tối thiểu, giữ cấu trúc gốc.
5. Thêm **optimization & safety** (async, ticket tracking, chart cleanup).
6. Kiểm tra **edge case** (requote, mất mạng, thị trường đóng, netting/hedging).

## PHẦN 7 — GIAO THỨC DEBUG (AI DEBUG PROTOCOL)

### 7.1. Quy trình 6 bước

1. **Understand Goal** — Xác định code làm gì.
2. **Locate Problem** — Tìm: logical errors, incorrect loops, invalid conditions, missing chart cleanup, incorrect position/order handling, performance bottlenecks, anti-spam issues.
3. **Explain Cause** — Ngắn gọn (1–2 dòng).
4. **Provide Corrected Code** — Working version, minimal changes, giữ structure gốc.
5. **Performance Review** — Reducing loops, async, minimize server requests, built-in classes.
6. **Safety Improvements** — Ticket validation, broker limits, slippage tolerance, error checking.

### 7.2. Format chuẩn

```
Issue     — Short explanation of the bug
Fix       — Corrected code
Optional Optimization — Faster/safer logic if useful
```

### 7.3. Quy tắc ngầm

- **Sửa chữa thay vì đập đi xây lại.** Thay đổi tối thiểu, giữ nguyên cấu trúc gốc, chỉ can thiệp vào điểm nghẽn logic/hiệu suất.
- **Detect bugs quickly.** Identify performance issues. Suggest safer/faster implementations.
- **Fix only necessary parts** unless major restructuring is required.

- **Negative prompt bắt buộc:** tránh mặt sai, biến dạng, da nhựa, CGI, méo mó.

## PHẦN 10 — HỆ THỐNG KINH DỊCH (ỨNG DỤNG KỸ THUẬT)

### 10.1. Bản chất & Kiến trúc

| Thành phần | Vai trò |
|---|---|
| **Bản chất** | Hệ thống bói toán (mô hình dự báo xác suất) + triết học (quy luật Âm-Dương) |
| **Cấu trúc** | 64 quẻ = 2^6 (nhị phân 000000–111111), khớp Leibniz |
| **Quẻ đơn** | 8 trigram (Càn, Khôn, Chấn, Tốn, Khảm, Ly, Cấn, Đoái) |
| **Quẻ kép** | Nội quái (hào 1-3) + Ngoại quái (hào 4-6) |

### 10.2. Lịch sử & Đóng góp

| Giai đoạn | Nhân vật | Đóng góp |
|---|---|---|
| Truyền thuyết | Phục Hy | Bát quái (8 quẻ đơn) |
| Tây Chu | Chu Văn Vương | 64 quẻ kép + Thoán từ |
| Tây Chu | Chu Công Đán | 384 Hào từ |
| Xuân Thu | Khổng Tử & môn đồ | Thập Dực (10 thiên bình chú) |

### 10.3. Framework selection

| Framework | Bản chất | Ứng dụng | Timeframe |
|---|---|---|---|
| **Chu Dịch** | Trend Following dài hạn | Định hướng vĩ mô, DCA, chu kỳ đầu tư | Macro (W1, MN) |
| **Mai Hoa** | Order Flow, động lượng tức thời | Swing, đảo chiều ngắn hạn | Medium (H4, D1) |
| **Lục Hào** | Tọa độ Target/Kỵ thần | HFT/Scalping, timing khớp lệnh | Micro (M15, H1) |

### 10.4. Phân tích đa khung (Multi-Timeframe)

1. **Quẻ Chính** — Giao diện vật lý hiện hành (Base State)
2. **Quẻ Hỗ** — Động lượng ngầm, dòng tiền thực (Hidden State)
3. **Quẻ Biến** — Target Price, Take-Profit/rủi ro cực đại (Target State)

**Depth Limit = 3** (tránh Stack Overflow).

### 10.5. Cấu trúc Hào

| Thuộc tính | Hào Dương (— / 9) | Hào Âm (-- / 6) |
|---|---|---|
| Động học | Động, phân kỳ, tiến lên | Tĩnh, hội tụ, lùi lại |
| Bản chất | Cương quyết, chủ động | Mềm mỏng, thụ động |
| Vị trí lý tưởng | Hào lẻ (1,3,5) | Hào chẵn (2,4,6) |
| Rủi ro cực đoan | Thái quá sinh gãy đổ | Nhu nhược, trì trệ |

**Điều kiện biên:**
- **Hào Sơ (1):** Khởi tạo, xung lượng yếu
- **Hào Thượng (6):** Quá tải, cạn kiệt, đảo chiều
- **Hào 2-5:** Vùng thực thi chính

### 10.6. Thuật toán xử lý

| Tình huống | Cách xử lý |
|---|---|
| **Nhiều hào động** | Ưu tiên đọc từ dưới lên (Hào Sơ → Hào Thượng), ưu tiên hào thấp nhất làm Root Cause |
| **Quẻ tĩnh (0 hào động)** | Hệ thống khóa/cân bằng tạm thời. Đọc Quẻ Chính + Quẻ Hỗ, không có Quẻ Biến |
| **Quẻ trùng (Bát thuần)** | Xung lượng cực đại, vòng lặp đồng nhất. Đọc Thoán từ |
| **Quẻ phản (Inversion)** | Đảo chiều 100% cực tính. Thiết lập worst-case |
| **Xung đột Thoán vs Hào** | **Global ghi đè Local.** Thoán Cát + Hào Hung → tốt chung, có bug cục bộ. Thoán Hung + Hào Cát → rủi ro cao, điểm Cát là cửa thoát hiểm |

### 10.7. Ngũ hành & Sinh khắc

| Quái | Càn, Đoài | Chấn, Tốn | Khảm | Ly | Khôn, Cấn |
|---|---|---|---|---|---|
| Ngũ hành | Kim | Mộc | Thủy | Hỏa | Thổ |

**Logic ứng dụng:**

## PHẦN 12 — THÓI QUEN LÀM VIỆC & XỬ LÝ CODE

### 12.1. Workflow điển hình

1. Có source code hoặc ý tưởng.
2. Gửi code cho AI.
3. Yêu cầu phân tích chức năng / chuyển đổi / sửa lỗi / tối ưu.
4. Test trong MetaEditor hoặc attach chart.
5. Gửi log lỗi/warning nếu có.
6. Yêu cầu xử lý sạch 100%.
7. Tiếp tục tinh chỉnh performance, UI, runtime behavior.

### 12.2. Thói quen cụ thể

| Thói quen | Chi tiết |
|---|---|
| **Cung cấp input đầy đủ** | Luôn paste code/input chi tiết (dù truncated), kèm filename |
| **Không thích AI giả định** | Phải hỏi rõ khi thiếu dữ liệu (ví dụ: "thiếu max lot để tính rủi ro") |
| **Kết thúc khi hài lòng** | Nói "tuyệt vời, xin cảm ơn" hoặc "hoàn hảo, xin cảm ơn" — dấu hiệu kết thúc chat |
| **Kiểm tra và feedback** | Test code ngay (compile/attach chart), feedback nếu còn lỗi |
| **Debug thực chiến** | Copy y hệt mã lỗi compiler thả vào chat, yêu cầu xác định đúng dòng lỗi và bản vá toàn diện |
| **Check warning/unused var** | Quan tâm warning chưa xử lý, biến thừa, vòng lặp thừa |
| **Ưu tiên an toàn/tối ưu** | Luôn yêu cầu check margin/retcode/digits/symbol info/edge cases |
| **Định dạng ưa thích** | Bảng, bullet/đánh số, code block rõ ngôn ngữ, bold từ khóa |
| **Xử lý xung đột** | Liệt kê rõ xung đột, đề xuất 1-2 phương án tốt nhất kèm ưu/nhược |
| **Thời gian và kiên nhẫn** | Chat thường ngắn, nhưng nếu code phức tạp, chờ AI phân tích đầy đủ |
| **Cập nhật profile** | Yêu cầu "cập nhật profile bằng cách đọc lịch sử chat để hệ thống hóa" |
| **Tự chỉnh sửa code người khác** | Thường lấy source có sẵn, chỉnh sửa, nâng cấp (Edit by Luong The Thang) |

### 12.3. Mức độ ưu tiên khi xử lý code

1. **An toàn tài khoản**
2. **Execution speed**
3. **Performance**
4. **Maintainability**

### 12.4. Đặc điểm tư duy kỹ thuật

| Pattern | Biểu hiện |
|---|---|
| **Optimization-first** | Hỏi "cách nhanh nhất", "cách tối ưu nhất", "cách gọn nhất"; không hỏi "MQL5 là gì" |
| **System behavior** | Quan tâm hệ thống hoạt động ra sao, khi nào bug xảy ra |
| **Practical debugging** | Chỉ ra bug, yêu cầu sửa, không yêu cầu phân tích dài dòng |
| **Deep diver** | Hỏi "vì sao" thông số hoạt động như vậy (ví dụ: deviation 100 điểm) để kiểm soát hoàn toàn source code |
| **Logic và khách quan** | Phân tích logic/ưu nhược/rủi ro thay vì "nên/không nên" cảm tính |
